# 公开产品审查与优化报告

审查日期：2026-10-30；许可证状态更新：2026-11-03。基线：main / 8896825。本轮结果保留为本地修改，未提交、推送、创建 Release 或公开发布。

## 1. 定位、用户与成熟度

**定位：Windows 优先、在修图之前使用的本地照片整理与选片工具。** 它把存储卡文件、JPG/RAW 拍摄单元、相册和人工决定连接起来。
最适合有批量拍摄习惯、使用 JPG 或 JPG+RAW、重视文件留在本机且能接受早期源码安装的摄影爱好者。
不适合期待手机云相册、多人共享、RAW 冲洗、视频剪辑或无人值守 AI 自动删片的用户。

最值得介绍的三个实际价值：

1. **成组整理**：JPG/RAW 不必作为两份照片分别筛选，附属文件和视频也能随批次保留。
2. **人工决定可持续使用**：对比、评分、标签、拆组、撤销和历史恢复，减少依靠资源管理器和临时笔记来回核对。
3. **导入和归档可核对**：来源检查、完整重复组识别、SHA-256 校验、进度、预览确认与数据库备份，保留来源卡文件。

核心链路已经超过技术演示阶段，具有个人生产使用记录和较完整回归。基础能力不依赖大模型。
但安装、异常退出及陌生人首次使用仍有门槛，**目前更接近可供小范围试用的个人工具，而非成熟通用开源发行版**。
代码许可已确定；在个人信息公开范围确定、安全更新实际进入运行环境之前，不建议直接扩大宣传。
完成这些门禁后，先邀请少量 Windows 用户试用比继续堆功能更有价值。

| 能力 | 实际成熟度与边界 |
|---|---|
| JPG/RAW 配对、相册、标签、评分、筛选、对比、撤销 | 已实现且有自动化回归；真实窗口及不同相机组合仍需用户试用 |
| 导入、视频/附属文件关联、正式归档 | 正常流程和多种冲突/中断有测试；永久失去来源时缺少安全退出入口 |
| 元数据、技术质量和统计 | 已实现；无 ExifTool 时基础 JPG 可用，厂商扩展兼容性仍需真实样本 |
| 本地模型 | 可选实验能力；有专门运行环境要求，不代表通用 GPU/模型兼容，不宜作为首次使用前提 |
| 修图、Lightroom | 参数化预览和只读预检/清单；不是完整修图器，不写 Lightroom 或 XMP |
| RAW、视频 | RAW 无解码预览，视频无播放/剪辑；支持保留不等于支持浏览全部格式 |
| Windows 发布 | 有独立窗口、内测打包与升级逻辑；未完成签名和陌生用户干净机器验收 |

### 安全与隐私判断

- 当前跟踪文本及本地可达历史的常见密钥模式扫描未发现高置信度凭据；这不保证不存在任何敏感内容。R04 的个人资料是实际存在的独立问题。
- HTTP 写操作有会话令牌、Host/Origin 限制和本机监听；不需要为当前定位增加账号。它们也不构成反向代理后的多用户权限系统。
- 复制/归档有路径边界、目标冲突拒绝、校验和备份，自动化覆盖相应异常；不将其描述为任何硬件故障都不会丢数据。
- Pillow 处理实际照片，安全更新有产品意义；前端 audit 的部分问题属于构建/测试工具，不据此宣称线上相册存在已证实远程攻击。
- 版本公告参考：[Pillow 13 发布说明](https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html)。
  代码授权边界参考：[GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

## 6. 新用户路径与后续执行顺序

新用户按 README 安装 Git/Python/Node → 克隆并安装 Python/前端 → 生成自己的配置并 doctor → 启动回环服务 →
“导入新照片”检查拍摄目录 → 新建相册并确认复制 → 预览确认归档 → 进入相册评分/对比。
安装依赖和核心 API 流程已实测；从全新系统安装开发工具、实际浏览器操作与真实相机兼容性仍未实测。

按收益/投入排序，后续只建议五项：

1. **作者确认个人信息公开范围，核对第三方许可**：高收益、低到中投入；自有代码已选 GPL-3.0-only。先确认资料保留范围，再修改文件，历史处理另行授权。
2. **受控更新运行环境并做干净 Windows 首次验收**：高收益、中投入；先核对任务空闲、保留备份，再升级依赖/重启。另找无历史环境机器按 README 完成一批 JPG+附属文件流程。
3. **设计中断导入的安全退出**：高收益、中投入；先明确未复制、已复制、已索引三种状态的保留/回滚规则，再实现预览、确认和崩溃恢复测试。不直接增加删除按钮。
4. **邀请少量目标用户试用并补两张真实截图**：高收益、低到中投入；观察能否独立找到导入、理解归档和找到相册，按实际失败改文案。
5. **整理可分发 Windows 试用包**：中收益、中到高投入；汇总第三方许可/安全、校验和与签名状态，完成干净机测试后再发布，不急于跨平台扩张。
