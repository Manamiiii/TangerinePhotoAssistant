# 本地模型与器材知识库策略

## 1. 原则

不使用单一视觉大模型直接决定评分和淘汰。系统先由 EXIF、传统图像算法和专用视觉模型生成可验证证据，再由视觉语言模型完成综合解释、构图点评和自然语言建议。所有模型离线运行、版本固定、结果可重算，人工判断优先。

## 2. 推荐模型栈

### 2.1 视觉语言模型

当前候选主模型为本机已有的 `Qwen-3-VL-8B-Instruct-heretic`。磁盘保留 BF16 Safetensors 权重，程序通过 bitsandbytes 在加载时使用 INT8 量化；它必须通过真实照片小批量基准后才参与正式建议。因为这是第三方改版，不能承担自动淘汰或最终评分。

如果 INT8 的速度、结构化输出或照片判断稳定性不理想，再比较官方 `Qwen3-VL-8B-Instruct` 的本地量化版本或较小的官方模型。

职责：

- 结合照片、EXIF、器材能力和专用检测结果生成拍摄复盘。
- 给出构图、背景干扰、姿态和修图方向建议。
- 对连拍候选解释“为什么推荐这一张”，不负责计算原始相似度。
- 输出严格结构化 JSON，所有结论带证据、置信度和可修复程度。

RTX 5080 16 GB 已验证能够完整加载 INT8 的 8B 视觉模型：模型内存 footprint 约 9.33 GB，CUDA 分配约 9.35 GB；实际带图片生成时，驱动报告的整卡显存通常约 14–15.7 GB，任务结束后释放到约 1 GB。大模型只处理待复核照片和连拍代表帧，不对 25,000 张照片无差别逐张生成长文本。

2026-08-10 的真实照片校准结果：1280px 的 v2 100 张基准为 100/100 成功、平均 133.6 秒/张；960px 的 v3 10 张为 10/10 成功、平均 42.4 秒/张，但一张把 0.00667 秒误写成 1/6.67 秒，并在高光过曝时建议提高 ISO。v4 直接提供换算后的快门文本并增加参数方向校验，同图复测已修正；5 张验证为 5/5 成功、平均 45.8 秒/张。推荐批次又发现“高 ISO 噪点却继续提高 ISO”及人物三脚架建议缺少静止前提，现已分别加入拒绝和人工复核规则。正式推荐批次因此固定使用 v4 和 960px，旧结果保留版本标识供比较，不覆盖。

现有模型位置：

```text
D:\LocalAI\models\qwen3-vl-8b-heretic-transformers
```

程序只引用该目录，不在 `TangerinePhotoAssistant` 或 C 盘缓存中创建副本。运行时量化不生成第二份权重；模型身份同时记录 `int8` 变体，避免以后不同精度的结果被误当成同一模型缓存。

当前实现可复用本机 ComfyUI 虚拟环境中的 CUDA PyTorch 与 Transformers 直接加载该目录，具体路径由本机 `config.toml` 配置。模型在独立隐藏进程中运行，主网页进程不导入 PyTorch；任务按照片逐条提交结果，因此个别解析错误或任务中断不会覆盖技术评分。运行采用 25/50/100/200/500 张可选批次，启动前备份数据库，页面展示平均耗时、预计剩余时间和实时 GPU 资源；任务可在当前照片完成后安全暂停、继续或取消。

### 2.2 相似照片与连拍聚类

首选候选：DINOv3 小型视觉骨干；若模型获取、许可或 Windows 部署不合适，使用 Apache-2.0 的 DINOv2 ViT-S/14 或 ViT-B/14。

职责：

- 生成图像向量，聚类近似照片。
- 识别相同场景、相近构图和动作变化。
- 与时间、文件序号、人脸和局部特征共同形成连拍组。

完全相同的文件仍使用加密哈希判断；感知向量不能代替文件哈希。

### 2.3 人脸、眼睛与姿态

- MediaPipe Face Landmarker：人脸关键点、眼部状态、头部姿态和遮挡辅助证据。
- 人物身份聚类：采用独立的人脸嵌入模型，具体实现需在许可审查和家人照片实测后确定。
- 身体姿态：采用轻量姿态关键点模型，检测肢体遮挡、关节截断和连拍动作差异。

人物美感、表情和姿态不可仅由单个分数决定；系统展示相对比较与原因，并允许一键纠正。

### 2.4 技术质量

优先使用可解释算法与小模型：

- 主体/眼部局部锐度、边缘扩散和模糊方向。
- 相机抖动与主体运动模糊的区别。
- 直方图、RAW/JPG 高光剪切、阴影、动态范围和白平衡。
- 噪点、压缩、暗角、畸变和地平线。
- 景深证据与多人焦平面关系。

审美质量模型只作为弱信号，不直接决定星级；不同题材分别校准，避免人像、星空和风景使用同一评分标准。

### 2.5 元数据与规则引擎

ExifTool 读取标准 EXIF 和富士厂商字段。规则引擎结合：

- 机身画幅、像素、机身防抖和对焦能力。
- 镜头焦距、最大光圈、镜头防抖和近摄能力。
- 快门、光圈、ISO、曝光补偿、焦距和拍摄模式。
- 题材、主体运动、现场光线和历史成功率。

规则不把缺失字段当作事实。无法读取对焦点、防抖开关或现场意图时，建议必须标为推测。

## 3. 器材知识库

器材信息有三个来源：

1. 扫描全部照片 EXIF，自动发现实际使用过的机身、镜头和常用参数。
2. 用户确认型号，并补充 EXIF 无法可靠表达的器材与使用习惯。
3. 将官方说明书或规格资料整理为本地、带来源的结构化记录。

建议记录：

- 机身完整型号、传感器画幅、像素、机身防抖、机械/电子快门和对焦能力。
- 镜头完整型号、焦段、最大光圈、镜头防抖、最近对焦距离和增距镜。
- 闪光灯、三脚架、滤镜和其他会影响拍摄建议的附件。
- 常用自动 ISO、快门下限、对焦模式、连拍模式和自定义设置。
- 已知偏好，例如希望保留环境感、接受的噪点程度和常用输出尺寸。

## 4. 选型验证

建立一组由用户人工标注的真实样本，覆盖女朋友人像、风景、宠物、父母、星空和大规模连拍。分别测量：

- 闭眼、失焦、运动模糊等问题的误判率和漏检率。
- 连拍分组准确率与最佳照片命中率。
- 拍摄问题解释是否得到画面与 EXIF 支持。
- 4B/8B 模型的速度、显存、稳定性和中文建议质量。

模型选型写入分析记录；升级模型不会覆盖人工评级，也不会直接改变历史成长统计。
