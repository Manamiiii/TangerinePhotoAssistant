# TangerinePhotoAssistant 完整方案

## 1. 产品定位

TangerinePhotoAssistant 是 Lightroom Classic 之前的本地选片与资料治理层。Lightroom 继续承担正式图库、非破坏性调整和导出；Photoshop 承担复杂精修。本程序解决 Lightroom 不擅长自动完成的存量目录审计、JPG/RAW 配对、大规模连拍选优、家庭人脸聚类、问题解释和长期统计。

## 2. 安全边界

- 阶段 1 到阶段 4 对 `D:\Photo` 全程只读。
- 不将图片、人脸特征、EXIF 或统计数据发送到网络。
- 不修改 JPG、RAW、PSD 或视频本体。
- 不覆盖已有 XMP；写入功能启用后也先备份并执行字段级合并。
- 目录移动必须生成 `move-manifest.csv`，包含来源、目标、配对关系和冲突检查，经人工确认后单独执行。
- 不实现永久删除；低质量照片只记录 `reject_candidate` 状态。
- 所有模型结论保存模型版本、置信度和原因，人工修改永远优先。

## 3. 数据组织

### 3.1 拍摄单元

相同基础文件名、拍摄时间接近且元数据一致的 JPG 与 RAW 组成一个 `Capture`。评分、人物、题材、连拍归属和修图建议附着在 Capture 上，而不是重复附着到两个文件。

### 3.2 事件

事件由现有目录、拍摄时间间隔、GPS 和用户命名共同确定。物理目录只表达事件：

```text
类别 / 年份 / YYYY-MM-DD_地点或事件
```

一级类别初步使用 `旅行`、`回家`、`日常`、`待整理`。最终分类以只读审计结果为准。

### 3.3 标签维度

- 人物：女朋友、父亲、母亲、其他人物；先聚类后由用户命名。
- 题材：人像、风景、宠物、星空、建筑、美食、其他。
- 工作状态：未评估、待复核、待修、修图中、已修、待导出、已导出、已归档；不重复表达选片入选/排除。
- 问题：闭眼、失焦、抖动、表情、姿势、遮挡、曝光、构图、背景干扰、近似次优。
- 地点：国家、省市、景点；仅从本地 EXIF 和用户输入产生。

## 4. 质量与星级

建议星级不直接等同于技术分数：

- 0 星：尚未评估。
- 1 星：明显失败或连拍中的弱版本；是否排除仍由人工选片结论决定。
- 2 星：技术一般但具有记录价值。
- 3 星：合格，可保留。
- 4 星：优秀，值得修图和分享。
- 5 星：代表作。

评分由四部分组成并分别展示：

1. 技术质量：人脸/主体清晰度、抖动、曝光、噪点、高光与阴影。
2. 人像状态：睁眼、表情、遮挡、姿态和肢体边界。
3. 构图质量：主体位置、地平线、裁切、背景干扰与视觉层次。
4. 相对优势：在同一连拍组内是否为最佳版本。

系统给出评分、问题原因和置信度；不会仅凭综合分自动淘汰。

## 5. 连拍选优

连拍分组结合以下信号：

- 拍摄时间间隔与相机序号连续性。
- 图像感知相似度和主体一致性。
- 人脸身份、场景和构图变化。

组内排序优先考虑主体锐度、睁眼、表情、遮挡、姿态、曝光和构图。界面显示最佳、备选、明显失败及原因。对明显不同的表情、动作或构图保留多样性，避免只留下数值最高但内容雷同的一张。

## 6. 修图建议

### 6.1 可自动计算

- 曝光、高光、阴影、白平衡和色偏建议。
- 地平线角度、裁剪比例和建议裁剪框。
- 镜头校正、暗角、锐化、降噪和色差建议。
- 人脸与主体局部亮度建议。

### 6.2 输出形式

- 第一阶段：文字建议、参数建议和低分辨率预览，不写 XMP。
- 第二阶段：经人工确认后，为 RAW 安全生成或合并 XMP。
- Lightroom Classic 导入后读取星级、关键词和兼容的 Camera Raw 参数。
- 复杂蒙版、生成式移除、液化和精细皮肤处理仅提供 Photoshop 待办建议。

系统保存“建议值”和“最终采用值”，用于逐步学习用户偏好的肤色、亮度、裁剪和风格。AI 蒙版等版本敏感能力必须经过 Lightroom 兼容性验证后再启用。

## 7. 拍摄问题分析与复盘

拍摄复盘与修图建议分开呈现：修图建议回答“这张照片现在如何改善”，拍摄复盘回答“为什么出现问题、下次如何拍得更好”。

### 7.1 分析依据

- EXIF：焦距、等效焦距、光圈、快门、ISO、曝光补偿、测光、闪光灯、相机与镜头。
- 富士元数据：在文件实际提供时，读取对焦、动态范围、胶片模拟和机内设置等厂商字段。
- 画面证据：主体/人脸清晰度、模糊方向、景深、噪点、高光剪切、阴影、白平衡、逆光、地平线和构图。
- 场景关系：人物是否运动、相机是否抖动、多人是否处于同一焦平面、焦点是否落在主体上。
- 同组对照：对同一连拍中参数相同但结果不同的照片进行比较，避免仅靠通用规则下结论。

### 7.2 问题分类

- 拍摄时已不可逆：严重失焦、主体运动模糊、眨眼、表情错失、关键高光完全溢出。
- 后期可部分改善：轻度欠曝、白平衡、噪点、地平线、裁剪和局部明暗。
- 操作与参数问题：快门下限过低、景深不足、ISO 策略不合理、曝光补偿不当、焦段或机位不理想。
- 无法可靠判断：缺少对焦点、稳定器状态或现场意图时，明确标注推测及置信度，不把经验规则写成事实。

### 7.3 建议形式

每张照片提供“现象 → 可能原因 → 证据 → 下次建议”：

```text
现象：人物眼睛轻微运动模糊
证据：眼部边缘存在方向性拖影；35mm、1/80s、f/2、ISO 400
可能原因：快门速度不足以凝固人物动作（高置信度）
下次建议：人物抓拍优先尝试 1/250s 或更快，允许自动 ISO 提升；保持眼部对焦
后期判断：锐化只能轻微改善，无法真正恢复细节
```

参数建议根据题材、焦距、主体运动、相机画幅和同一用户的历史结果动态计算，不机械套用单一的“安全快门”公式。系统还会汇总高频问题，例如某焦段下快门过慢、逆光人脸经常欠曝或大光圈多人合影景深不足。

## 8. 统计体系

### 8.1 拍摄行为

- 年/月/事件拍摄量，题材和人物占比。
- 相机、镜头、焦段、光圈、快门、ISO 分布。
- 连拍组数量、平均长度和最大连拍组。

### 8.2 选片结果

- 各事件的合格率、精选率、待淘汰率。
- 模糊、闭眼、曝光、构图等问题占比。
- 女朋友人像的连拍保留率和最终修图率。

### 8.3 成长分析

- 同题材、相似条件下的 3 星以上比例趋势。
- 技术失败率、重复拍摄率和选片效率趋势。
- 常用参数与失败问题的关联，例如慢快门与抖动、高 ISO 与噪点。
- 人工最终评分作为成长主指标，模型分数仅作辅助，避免模型升级造成假趋势。
- 高频拍摄问题随时间的变化，以及采纳参数建议后的改善幅度。

## 9. 技术架构

### 9.1 后端与任务系统

- Python 3.12；核心任务可断点续跑、可取消、可审计。
- SQLite 保存目录、标签、评分和任务状态；向量索引用于相似照片和人脸聚类。
- ExifTool 作为 RAF/JPG/视频元数据的权威读取层。
- GPU 推理由 RTX 5080 执行；CPU 负责元数据、哈希和任务调度。
- 图像只解码为分析所需尺寸，RAW 优先读取嵌入预览，候选精选才做高成本解码。

### 9.2 本地界面

后端提供本机 API，界面采用 React/Vite。界面只绑定回环地址，不提供公网访问：

- 收件箱与事件确认。
- 连拍组对比和同步缩放。
- 人脸簇命名与合并/拆分。
- 星级、问题标签和修图建议复核。
- 单张照片的拍摄复盘：EXIF、问题证据、可修复程度和下次拍摄建议。
- 统计仪表盘和 Lightroom 导出中心。

### 9.3 数据实体

- `FileAsset`：路径、大小、哈希、格式、EXIF、衍生关系。
- `Capture`：JPG/RAW 拍摄单元。
- `Event`：日期、地点、类别和目标目录。
- `BurstGroup`：近似照片组与排序结果。
- `PersonCluster` / `FaceInstance`：本地人脸聚类和人工命名。
- `Assessment`：分项质量、问题、解释、模型版本和人工覆写。
- `EditSuggestion`：建议参数、预览、采用状态和 Lightroom 映射。
- `CaptureCritique`：拍摄问题、画面证据、EXIF 依据、置信度和下次建议。
- `OperationManifest`：所有计划写入或移动操作及审核状态。

## 10. C/D 盘空间策略

C 盘为 Samsung 9100 PRO NVMe，D 盘为 4 TB 机械硬盘。配置如下：

- C 盘应用缓存默认上限 40 GB，使用 LRU 自动回收。
- Lightroom 活动目录和标准预览放 C 盘以提高浏览体验；1:1 预览定期丢弃，智能预览按需创建。
- 数据库、模型、报告和长期备份放 D 盘。
- Lightroom 目录从 C 盘定期备份到 D 盘；未来仍需外置介质提供真正的异盘备份。
- 空间上限可配置，程序在写缓存前检查剩余空间并保留安全余量。

## 11. 实施阶段与验收

### 阶段 A：只读审计

- 扫描全部目录、格式和 EXIF。
- 形成 JPG/RAW/衍生文件配对报告。
- 统计现有目录、日期跨度、相机镜头和疑似事件。
- 验收：不产生任何原片写入；重复运行结果稳定；扫描可断点续跑。

### 阶段 B：事件与目录方案

- 自动提出事件边界、类别、日期和地点名称。
- 生成目标目录预览和冲突报告。
- 验收：用户可逐事件修改；只生成 manifest，不移动照片。

当前进度：已实现基于目录日期、事件标题和实际拍摄日的第一版事件建议；能够把同一日期地点下原先分开的“宝贝”和“风光”目录合并为同一事件，并把教材素材排除在个人摄影统计之外。尚未开放事件确认和物理移动。

### 阶段 C：连拍、重复与质量分析

- 完成感知相似分组、连拍选优、模糊/闭眼/曝光等检测。
- 验收：抽样建立人工基准；分别评估漏检、误判和最佳照片命中率。

当前进度：已实现基于时间间隔、相机型号和文件序号的元数据候选分组。下一步加入画面向量，对候选组进行相似度拆分和组内选优。

### 阶段 D：人物与题材

- 本地人脸聚类，由用户命名女朋友和家人。
- 完成风景、宠物、星空等多标签分类。
- 验收：所有身份可纠正；特征不离开本机；支持彻底清除人脸数据。

### 阶段 E：修图建议与 Lightroom

- 生成文字建议、预览和基础参数。
- 验证 XMP 与当前 Lightroom Classic / Camera Raw 版本兼容性。
- 验收：现有边车不被覆盖；导入 Lightroom 后评级、关键词和参数一致。

### 阶段 F：统计与长期维护

- 建立拍摄、选片和成长仪表盘。
- 支持新增照片增量扫描，不重复分析未变化文件。
- 验收：统计可追溯到具体照片；模型升级不改写人工评分。

## 12. 第一轮开发范围

第一轮只实现阶段 A：安全配置、只读索引、EXIF 提取、JPG/RAW 配对、目录与格式报告、断点续跑和日志。AI 模型、文件移动、XMP 写入和 Lightroom 自动化不在第一轮启用，避免在基础数据模型尚未验证时扩大风险。
