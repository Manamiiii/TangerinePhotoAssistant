## 大图库设计结论

万张级使用不依赖人工逐条查看全量结果。默认流程是“聚合 → 风险排序/稳定抽样 → 人工队列 →
相册或单张下钻”：

- 首页按每日预算展示建议量和总积压，不把全部历史问题包装成当天任务。
- 技术、模型、完整性和任务异常均有稳定状态、重新出现语义与可找回历史。
- 图库和相似组在 SQLite 中完成筛选、折叠和分页；前端不加载全部 ID 执行隐式批量写入。
- 文本搜索防抖，分页请求可取消并带请求代次保护；写后只失效相关领域。
- 已完成 schema 32 正式库只读基线及 10k/100k 合成复测；统计复用单次查询内的照片关联，
  图库先分页 ID 再计算展示字段，未引入长期结果缓存、数据库迁移或新分页语义。
  数值、等价性与测量方法见 [性能基线](PERFORMANCE_BASELINE.md)。
- 缩略图生成最多同时解码 2 张，同图同尺寸请求合并；命中缓存不解码，列表/小图请求 320px，
  中图/大图保留 640px。没有全库预生成、后台预取或 GPU 任务。
  新版优先从同源版本的大尺寸缓存生成小图，不放大、不改变方向；损坏衍生图回退只读原片。
  缓存维护改为图片发送完成后执行，同一时刻最多一次、冷却 30 秒，遍历复用目录项元数据。
  近期 30 秒访问的缩略图暂不回收，容量目标可短时超出；后续图片请求重试回收。持续清理失败
  会限制新缓存增长并返回可重试 503，不影响已有缓存命中；不引入永久后台线程或全库预生成。
- 图库页码使用请求目标而不是上一份响应，加载时仍能连续翻页；页码输入回车/失焦提交，
  移除搜索后的重复分页防抖。上下分页条、骨架占位和页内失败重试避免误操作上一页照片。
  图库可视区域及临近缩略图最多 4 个下载，切页取消排队及在途下载，释放对象 URL；
  浏览器缓存仍复用。实机浏览器已核验连续 1→4 页、输入第 12 页和版本显示，未写人工数据。
  当前页前台图片全部空闲 600ms 后，可串行预加载下一页前 8 张缩略图；预加载只有一个低优先级
  槽位，新可见图片直接抢先。切页、改筛选、改显示尺寸、隐藏页面、打开详情、开始后台任务或
  30 秒超时都会取消剩余项；失败不重试、不显示错误，也不持有预取的评分或分组数据。
  设置顶部也显示后台版本、构建、schema，并说明窗口“应用”菜单和离线包检查入口。
  版本正文与标题共用 24px 水平内边距；系统维护页统一 20px 模块间距，避免标题卡与异常卡贴合。
- 参数分布与条件关联共用 `parameter_buckets.py`，按常用参数边界分档，焦段统一使用 EXIF
  的 35mm 等效值，缺失不混入实际焦距。原始 EXIF 保持不变，无需重扫或重跑模型。
  新条件键带 v2 版本；旧常用视图/深链接保持旧区间语义。观察卡片使用独立标题和等宽网格。

## 正式数据安全边界

- 不修改 `D:\Photo` 中任何文件。
- 未明确授权不复制、移动、删除、重命名或覆盖真实照片。
- 不自动写 XMP，不自动操作 Lightroom 目录。
- 不干扰 ComfyUI 或其他 GPU 任务，不自动启动全量技术或模型分析。
- 设置可随时修改路径，但只在重启后生效；不自动搬运旧工作区、数据库或缓存。
- schema 升级必须在任务空闲时通过正常服务启动，并核对升级前备份、完整性与健康接口。
