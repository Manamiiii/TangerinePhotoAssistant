# 本机数据保留与清理规划

2026-09-22 只读盘点。本文是实施边界与候选策略，**没有启用定时清理，也没有删除文件**。
只枚举明确的产物目录，不进入 历史原片目录 或正式 `Photos`，不跟随符号链接和目录联接。

## 目录角色

具体路径由每位用户的本机配置和数据库活动根决定。下表不代表已启用自动清理；
私人盘点的文件数、占用和路径保存在本机，不提交到仓库。

| 位置 | 用途与保留规则 |
|---|---|
| `<工作目录>/AlbumArchive` | 归档凭据与恢复资料，保留 |
| `<工作目录>/Backups` | 升级、导入、改名和恢复前备份，保留 |
| `<工作目录>/Reports` | 报告与审计材料，先区分用途，不按日期直接删除 |
| `<缓存目录>/thumbnails` | 可重建缩略图，仅按已配置的缓存边界维护 |
| `runtime/` 中的安装包、导入凭据、维护记录及私人原文 | 仅本机留存、不提交；不纳入一般缓存清理 |

凭据目录不纳入内容读取或清理。不能将“移出活动工程”报告为“永久删除”。

## 分类规则

1. **可重建缩略图**：继续使用现有容量上限与响应发送后的维护。后续若扩展清理，
   必须跳过在途生成和正在提供响应的文件，只处理真实缓存根内的普通文件。
2. **照片导出 ZIP、临时预览**：未来可把超过 30 天、未被在途任务引用的内容列为候选；
   默认只预览，显示文件名、用途、大小、生成时间及可否重建。不能把仍在生成的 `.partial`
   当作垃圾；必须先确认无对应任务，无法确认就保留。
3. **诊断包与普通报告**：可以建议保留最近 90 天，但审计、导入校验及用户主动留存的记录除外。
   文件名不能作为唯一用途证明；无法识别的内容不进入自动删除候选。
4. **归档计划、已完成归档凭据、数据库/设备恢复前备份**：不按年龄清理。
   先建立记录到备份的引用关系和完整性核验，再单独设计用户可审核的淘汰规则。
   所有未完成、暂停或损坏的记录及其引用文件必须保护。
5. **正式安装包、升级回退资料、验收记录**：保留。历史版本淘汰属于发布管理，
   不和缓存清理合并处理。
6. **分析结果、工作项、人工历史**：属于业务数据库，不在文件清理中删除。
   后续先明确历史查询与恢复需求，不以“过期”作为直接删行依据。

30/90 天是后续设计的候选阈值，尚未成为配置或生效规则。现有配置中的总缓存容量
不等于对整个工作目录实施了容量管理；不能据此承诺报告和备份会自动回收。

## 后续实施步骤与验收

1. 建立只读产物清单，记录类型、文件身份、大小、修改时间、任务/恢复引用、保留理由。
   先覆盖既有产物，不依赖人工猜测业务用途。
2. 输出保护项与候选项的预览和总大小；不包含照片目录、凭据、安装包和保护的恢复资料。
3. 如以后加入执行入口，执行前重新核验路径、文件身份与引用状态；预览后变化的文件跳过，
   确认无任务占用才处理。操作结果明确区分删除、移出、跳过与失败。
4. 自动回归仅使用自动清理的临时目录，覆盖目录联接逃逸、并发生成、预览后替换文件、
   坏 JSON、待恢复归档和备份引用。不得通过正式库制造这些条件。
5. 真正删除恢复资料或真实照片仍需另行授权；自动审批拒绝的永久删除不得换工具绕过。

是否需要释放空间应以本机只读盘点为准，不应为了减少文件数量删除正式资料。
