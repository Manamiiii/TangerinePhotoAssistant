# Windows 当前验收清单

本文只保留当前 schema 32 和日常功能回归。历史版本验收记录由 Git 保存，不再把 schema 27–31
的重复步骤叠加在主清单中。除明确说明外，不运行分析任务，不修改照片、XMP 或 Lightroom。

## 1. 启动前保护

1. 拉取 `main`，核对工作区干净。
2. 尝试读取 `http://127.0.0.1:8765/api/health` 和 `/api/tasks/current`。
3. 若任务为 `running` 或 `paused`，不重启、不结束进程，等待或按该任务自己的安全入口处理。
4. 记录正式数据库和备份目录的最新修改时间；不要手工复制、移动或重命名数据库。
5. 不启动 ComfyUI 竞争的模型任务，不运行新的全量技术检测或模型分析。

## 2. 启动壳与 schema 32

当前正式库最近一次只读核对仍为 schema 26，第一次点击桌面快捷方式会执行安全升级。

1. 服务未运行时点击桌面 “TangerinePhotoAssistant”，应隐藏启动并在健康检查后打开页面。
2. 大库完整性检查可能持续数分钟；启动壳最多等待 15 分钟。等待期间再次点击只能复用同一 PID，
   不得产生第二个升级进程。
3. `D:\PhotoLibrary\Backups\AnalysisDatabase` 应只新增一份
   `catalog-pre-schema32-from26-*.sqlite3`。
4. 用只读连接分别执行主库与该备份的 `PRAGMA integrity_check`；两者都必须为 `ok`，备份 schema
   为 26，主库 schema 为 32。
5. `/api/health` 应返回 `status=ok`、`mode=local-only`、`schema_version=32`；
   `/api/tasks/current` 不应出现自动启动的扫描或模型任务。
6. 服务已运行时再次点击快捷方式，应直接复用，不新增服务进程或影响当前任务。
7. 端口冲突、缺少 `.venv`、`web/dist` 或 `config.toml` 时应明确报错且不结束其他进程；日志仅写
   `runtime/launcher`，不得包含照片内容。

## 3. 万张级工作流回归

### 首页与图库

1. 首页显示今日建议量、预计时间和总积压；打开首页不得触发扫描或分析。
2. 常用视图可保存、恢复、删除；搜索停顿约 300ms 后更新，不闪空或丢字。
3. 列表/小图/中图/大图保持机身、镜头、JPG+RAW、相册/相似组、大小、评价和技术健康度语义
   一致；时间只显示一次，大小按 B/KB/MB/GB 自适应。
4. 图库筛选、排序、分页、相册上下文和详情可通过 Hash 深链接恢复；非法参数回退安全默认值。
5. 批量管理只影响明确勾选的最多 500 张；JPG/RAW 导出只在报告目录创建副本。

### 相似组选片

1. 可按全部/相册、待选状态、置信度和时间筛选，低置信组优先；筛选本身不写数据。
2. 人工拆分、移出、逐步撤销和恢复自动识别均只改 SQLite，刷新后语义稳定。
3. 技术推荐/兼顾差异/拍摄顺序不改变人工结论；差异信号不得冒充动作或表情识别。
4. 低风险批量操作必须先预览，最多 100 组，只把技术推荐标为保留，不自动排除；产生 5% 稳定
   抽检并可整体撤销。批次后有新人工修改时应拒绝覆盖式撤销。

### 质量与模型治理

1. 照片复核默认只显示当前问题队列；已核对、忽略、7 天后和重新打开均可找回。
2. 技术检测与模型分析标题、来源和等高摘要一致；无模型结果不保留无含义空白。
3. 模型结果可按风险、稳定抽样、固定基准、版本、题材、相册、月份和人工状态筛选。
4. 固定基准只使用已有结果，不读取照片或启动 GPU；扩大批次受覆盖率、样本量、错误率和未处理
   高风险项门禁约束。
5. 详情中的星级、可信度、标签、保留理由和参数化方案保存后可恢复；预览只使用缓存缩略图。

### 完整性与任务异常

1. 完整性差异按状态和目录分页下钻；持续不变的已处理项不重新出现，消失后再现或类型变化才
   标记重新出现。
2. 导出当前差异范围只使用既有检查结果，不触发扫描；文件含相对路径，只在本机使用。
3. 后台任务失败按任务家族与安全错误类型合并，接口不泄露真实路径或异常正文；后续同类任务成功
   时自动标记已恢复。
4. 脱敏诊断 ZIP 只包含白名单汇总；人工数据备份不含照片、绝对路径、GPS、缩略图或模型正文。

## 4. 已验收核心功能抽查

1. 相册照片/相似选片/质量结果切换保持同一相册范围，返回回到相册列表。
2. 普通照片只有星级、标签和工作状态；保留/排除仅出现在相似组内。
3. 详情可滚动到底且底层不动；左右键、参数解释、沉浸查看、缩放和 `Esc` 正常。
4. 扩展 EXIF、JPG 直方图、分项技术健康度、模型观察/拍摄建议/后期建议来源清楚。
5. 标签管理支持自定义词新增、改名、停用和恢复；使用中的词不丢失关联。
6. 摄影统计的数量/占比、月份、器材、题材、条件关联和成长趋势可钻取；稀疏数据不显示误导 0%。
7. 设备管理的机身、镜头和附件 CRUD、拥有/隐藏状态、本地/内置图片及许可证入口正常。
8. 设置可打开实际目录，保存前校验并备份，重启后生效；不搬运旧目录内容。
9. Lightroom 只读预检不打开 `.lrcat`，不删除 `.lrcat.lock`，准备清单执行字段保持为 0。

## 5. 正式库只读性能基线

完成 schema 32 升级且服务空闲后，按 `PERFORMANCE_BASELINE.md` 使用 `--existing-database` 运行。
工具必须拒绝非当前 schema、拒绝覆盖报告、不读取照片，也不在报告中保存数据库路径。记录结果后
再决定是否继续优化深页或统计查询。

## 6. 隔离写入验收

新增/编辑/删除标签或设备、相册附件、人工恢复和少量导入等写入测试只使用 Mac 样例或临时目录。
正式环境除用户日常人工结论外，不为验收制造照片、完整性差异、任务失败或模型结果。
