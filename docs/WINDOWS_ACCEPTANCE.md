# Windows 验收清单

回到正式 Windows 主机后，可按下面顺序验收。除明确标注的步骤外，不需要运行全量分析。

> 状态：2026-08-14 已按本清单完成本轮正式数据验收。以下步骤保留为后续版本回归基线；
> 再次执行写数据库的项目时仍应使用可恢复的测试内容，不得修改真实照片文件。

## 启动壳验收

1. 首次只运行 `install-windows-launcher.cmd`，确认桌面和开始菜单出现快捷方式；该动作不得启动
   服务、扫描图库、修改配置或数据库。
2. 后台服务未运行时点击快捷方式，应不显示控制台窗口；正常 schema 备份/升级和健康检查完成
   后自动打开 `http://127.0.0.1:8765`。升级耗时较长时最多等待三分钟，不得并行重复启动。
3. 服务已运行时再次点击，应直接复用并打开页面，不新增服务进程，不影响 `/api/tasks/current`。
4. 用隔离端口测试冲突保护：端口由非 Tangerine 程序占用时应显示错误且不结束对方进程。不要
   为此占用正式的 8765 端口或中断现有后台任务。
5. 缺少 `.venv`、`web/dist` 或 `config.toml` 的隔离副本应给出明确错误；启动失败时仅在
   `runtime/launcher` 生成本地日志，不应出现照片内容、自动模型任务或原片写入。

## 0. 2026-08-25 schema 32 相似组选片规模化验收

本节不需要更新相似分组或运行任何模型。启动前确认 `/api/tasks/current` 没有运行或暂停任务；
核对升级备份及正式库 `PRAGMA integrity_check` 均为 `ok`，健康接口报告 `schema_version=32`。

1. 打开“相似组选片”，待选组应显示高置信、一般或需重点看，并可组合进度、置信度和待选时间
   筛选。低置信组应优先排列；筛选不会修改任何选片结论。
2. 点击“批量预览”，只应列出技术检测齐全、视觉距离小、推荐健康度不低于 75 且领先至少 5 分
   的待选组。预览不会写数据库；相册内进入时仅预览该相册。
3. 在隔离测试数据上确认批次后，只应把每组技术推荐标成“保留”，其他照片不得自动排除；批次
   自动产生 5% 抽检（不足 20 组时至少 1 组）。
4. 抽检可进入原组对比并标记“正确/有问题”。最近批次可撤销；若批次中的选片此后又被人工
   修改，撤销应被拒绝，不能覆盖更新的人工结论。
5. 人工数据备份应包含批次、撤销和抽检状态，但仍不包含照片、绝对路径或模型结果正文。

## 0A. 2026-08-25 schema 31 固定模型审计基准验收

本节不要求运行模型。启动升级前确认 `/api/tasks/current` 没有运行或暂停任务；核对升级前备份和
正式库的 `PRAGMA integrity_check` 均为 `ok`，`/api/health` 报告 `schema_version=32`。

1. 打开“质量分析 → 模型结果”，应看到“固定基准集”。建立 100 张基准只使用已有模型结果并
   写入 SQLite，不应读取照片、启动 GPU 或创建模型任务；已有结果不足 100 张时使用全部可用项。
2. 基准覆盖摘要应显示相册、题材、月份、置信度层和问题层数量；再次点击补足且没有新增结果时，
   成员数量不变。审计队列选择“固定基准集”后可查看成员。
3. 模型结果可组合提示词版本、相册、题材、月份、置信度、问题类型、人工结论和处理状态筛选；
   5% 稳定抽样应按照片保持稳定，不能因新增一次模型运行而整体换样。
4. 版本门禁应展示分析覆盖率、人工复核覆盖率、不准确率和未处理高风险项。条件未满足时不得批准
   扩大，也不得运行推荐批次；“验证 10 张”仍可用于逐步补齐固定基准。
5. 固定基准成员和版本人工结论应进入人工数据备份；导出仍不包含照片、绝对路径或模型结果正文。

## 0B. 2026-08-25 schema 30 后台任务异常恢复验收

本节不要求人为制造任务失败。正常启动升级前先确认 `/api/tasks/current` 没有运行或暂停任务；
确认生成升级前备份，正式库和备份的 `PRAGMA integrity_check` 均为 `ok`，`/api/health` 报告
`schema_version=32`（本节功能最初在 schema 30 落地）。

1. “系统维护 → 后台任务异常”默认显示当前待处理，可切换新发现、重新出现、稍后处理、已核对、
   已忽略、已恢复和全部状态；没有历史异常时显示空状态即通过。
2. 若已有自然发生的失败，可将其设为已核对、7 天后或忽略，并能在相应筛选中找回；重新打开
   后回到当前队列。不要通过破坏照片、目录权限或启动模型来制造异常。
3. 同一任务家族的相同失败只显示一项；已核对后若自然复发应显示“重新出现”。同类任务下一次
   成功后应自动进入“已恢复”。首页按异常任务家族显示入口，不逐次堆叠失败日志。
4. 任务卡和接口只显示 `PermissionError`、`OSError` 等安全错误类型，不应泄露照片路径或底层
   异常正文；详细排障仍使用本机日志和脱敏诊断包。

## 0C. 2026-08-25 schema 29 完整性调查验收

本节不要求制造正式库差异。正常启动升级后，确认生成一份升级前备份，正式库和备份的
`PRAGMA integrity_check` 均为 `ok`；当前代码的 `/api/health` 应报告 `schema_version=32`（本节功能
最初在 schema 29 落地）。

1. 若上次历史存档或活动图库检查已有差异，首页应出现独立“完整性差异待调查”入口，不能混在
   照片复核入口里；没有差异时不显示该入口。
2. 进入“系统维护 → 调查差异”，默认只看当前待调查；可切换新发现、重新出现、稍后处理、
   已核对、已忽略、已解决和全部状态。
3. 对一条可恢复测试差异选择“已核对”，它应退出当前队列并能在已核对中找回；重新打开后回到
   当前队列。7 天后和忽略具有相同的可找回语义，只写 SQLite。
4. 再次运行只读检查时，持续不变的已核对差异不得重新变成待办；若它在一次检查中消失、以后
   再出现，或差异类型发生变化，则应标为“重新出现”。不得为验收修改或损坏真实照片。
5. 差异较多时应先显示当前层级的目录汇总，可从“全部目录”逐层下钻，面包屑返回上级；目录
   计数和下方文件总数应随调查状态筛选同步变化，Windows 路径不能因反斜杠而无法下钻。
6. “导出当前结果”应只导出当前调查状态和目录范围，并提供 CSV、JSON 下载。文件包含相对路径，
   只用于本机调查；导出不应触发磁盘扫描、照片复制或修复操作。
7. 同一范围至少有两次检查后，应出现“最近完整性变化”，分别展示差异总数、相对上次的净变化、
   新出现、已恢复和类型变化；只有一次检查时不展示没有比较意义的趋势模块。

## 0D. 2026-08-25 schema 28 工作队列精简验收

本节只验证人工状态收敛，不需要重跑技术检测或模型。启动前仍须先确认
`/api/tasks/current` 没有 `running` 或 `paused` 任务。当前正式库若仍为 schema 26，首次启动
会直接生成 `catalog-pre-schema28-from26-*.sqlite3`；若已经验收过 schema 27，则文件名为
`catalog-pre-schema28-from27-*.sqlite3`。正式库和该备份的 `PRAGMA integrity_check` 都必须为
`ok`，启动后的 `/api/health` 应报告 `schema_version=28`。

1. 首页“待处理”只显示最多 30 项今日建议复核及预计时间，同时保留技术、模型总积压作为说明；
   不能把全部历史积压伪装成今天必须完成。可在应用设置把“每日建议复核量”改为 20，保存并
   按提示重启后首页应采用 20；验收后可改回 30。
2. 打开“质量分析 → 照片复核”，默认应为“发现问题 + 当前待处理”。任选一张测试照片点击
   “已核对”，卡片应退出当前队列；切换到“已核对”应能找回，点击“重新打开”后回到当前队列。
3. 任选另一张点击“7天后”，它应退出当前队列并出现在“稍后处理”；任选一张点击“忽略”，
   它应只出现在“已忽略”。这些操作只写 SQLite，不修改照片。
4. 在“模型结果”验证“当前待处理 / 稍后处理 / 已忽略 / 已核对”筛选。详情中保存准确性结论后，
   对应模型结果应自动成为已核对；无需逐条复核全部模型结果。
5. 在照片图库组合相册、器材、状态或日期筛选，从“管理视图”保存当前筛选；常用视图应直接
   出现在筛选栏下方并标明当前生效项，刷新后仍可恢复。删除只清理浏览器本地预设，不修改照片
   或数据库。
6. 批量管理可以逐页累加明确勾选，但单次最多 500 张，界面必须持续说明不会自动作用于全部
   筛选结果；尝试让本页全选超过上限时应在前端阻止。服务端影响预览、持久任务和撤销清单完成
   前不会开放全匹配写入。
7. 若正式库存在技术检测读取错误，“照片复核 → 读取失败”应只显示通用处理建议，不展示本机
   路径或原始异常正文；可核对、忽略、稍后和重新打开。没有读取错误时显示空队列即为通过，
   不要为了制造样例重跑全量检测或损坏文件。
8. 首页待处理和照片/模型复核卡片应显示最早积压年龄，队列中较早发现的同优先级项目在前；
   “今天发现”不显示成误导性的 0 天积压。
9. 首页待处理摘要应同时区分今日建议量和总积压，显示预计处理时间、新项/重新出现数量与当前
   最高优先事项；这些数字只读取数据库，不得因打开首页启动扫描或分析。

## 0E. 2026-08-24 schema 27 历史验收

今晚优先完成本节即可；后面的长清单不需要全部重跑。开始前先拉取 `main`，确认提交为
`284ef41` 或更新，并检查当前服务任务：

```powershell
git switch main
git pull --ff-only origin main
git status --short --branch
try { Invoke-RestMethod http://127.0.0.1:8765/api/tasks/current } catch { $_.Exception.Message }
```

若任务接口显示 `running` 或 `paused`，不要重启服务。若返回 404，说明当前是没有该接口的旧服务；
先从旧页面或原终端确认没有扫描、质量、详情补全或模型任务，再按正常方式关闭旧服务，不要直接
结束未知 Python、ComfyUI 或 GPU 进程。

1. 启动前记录 `D:\PhotoLibrary\AnalysisDatabase\catalog.sqlite3` 的修改时间，并查看
   `D:\PhotoLibrary\Backups\AnalysisDatabase` 当前最新备份；不要手工复制、移动或改名数据库。
2. 通过 `start-photo-assistant.cmd` 正常启动。首次打开 schema 26 正式库时，应新增且只新增一份
   `catalog-pre-schema27-from26-*.sqlite3`，然后正式库升级为 schema 27。
3. 用下面的只读命令同时核对正式库与最新升级前备份。正式库应为 schema 27、备份应为 schema
   26，两者 `PRAGMA integrity_check` 都必须为 `ok`：

```powershell
@'
import sqlite3
from pathlib import Path

catalog = Path(r"D:\PhotoLibrary\AnalysisDatabase\catalog.sqlite3")
backup_root = Path(r"D:\PhotoLibrary\Backups\AnalysisDatabase")
backup = max(backup_root.glob("catalog-pre-schema27-from26-*.sqlite3"), key=lambda p: p.stat().st_mtime)
for path in (catalog, backup):
    connection = sqlite3.connect(f"{path.resolve().as_uri()}?mode=ro", uri=True)
    try:
        version = connection.execute("SELECT version FROM schema_info").fetchone()[0]
        integrity = connection.execute("PRAGMA integrity_check").fetchone()[0]
        print(path, "schema", version, "integrity", integrity)
    finally:
        connection.close()
'@ | .\.venv\Scripts\python.exe -
```

4. 打开 `http://127.0.0.1:8765/api/health`，确认 `status=ok`、`schema_version=27`、
   `mode=local-only`。`ai_audit_backfill.status` 最终应为 `complete`；若短暂显示 `running`，等待后
   刷新，不要因此启动模型分析。
5. 打开 `/api/system/ai-audit-backfill`，确认没有 `failed`。若失败，先记录错误类型，不要连续点击
   重试；保留数据库和日志后再排查。
6. 在质量分析的模型结果中依次切换“高风险优先 / 5% 稳定抽样 / 全部记录”，标题和数量应随
   当前队列改变；旧模型结果不需要重跑。
7. 在图库设置一个相册、筛选、排序、分页并打开照片，复制当前 Hash 到新标签页，确认恢复相同
   范围和详情；非法日期或 ID 应回退安全默认值。
8. 在应用设置修改一个字段但不保存，点击左侧其他主功能，应出现放弃修改确认；选择取消必须留在
   设置页，选择离开不得写配置。
9. 浏览图库首页、深页、一个大相册折叠页和摄影统计。正式库约 13.8k Capture，不应出现秒级
   卡死或内存持续增长；无需在正式库运行合成基准工具。
10. 全程不要运行新的全量质量/模型分析，不写 XMP，不操作 Lightroom 目录，不修改照片文件。

上述 10 项通过后，schema 27 可以视为完成 Windows 正式库验收，再开始 schema 28 的人工工作
队列迁移。Mac 可以提前验收 UI、深链接和隔离样例，但不能替代第 1–5 项的正式数据库检查。

## 1. 启动与只读状态

1. 双击 `start-photo-assistant.cmd`。
2. 确认打开 `http://127.0.0.1:8765`。
3. 在“系统维护”确认历史原片和活动图库最近结果均为缺失 0、变化 0、新增 0。

## 2. 新照片入口

1. 打开“照片图库 → 更新图库”。
2. 核对目录为 `D:\PhotoLibrary\Photos\待整理`。
3. 点击“在资源管理器中打开”，确认打开正确目录。
4. 暂不放入正式新照片也可以关闭窗口；该操作不会扫描或修改文件。

## 3. 相似照片分组

建议先选不重要的历史相似组测试：

1. 点击“调整分组”，拖一张照片到空白组。
2. 取消，确认分组没有变化。
3. 再次调整并确认，刷新页面，确认结果仍保留。
4. 点击“恢复自动识别”，确认同一次人工调整整体撤销。
5. 再次确认调整，点击保存提示中的“撤销”，确认立即回到保存前状态。
6. 打开“分组历史”，恢复一个较早版本，确认刷新后仍保留；再恢复自动识别，确认历史记录仍可查看。

“移出分组”只改变 SQLite 中的分组覆盖，不移动、删除或改写照片。重新运行视觉分析后，已确认的人工分组仍会保留；只有“恢复自动识别”会撤销它。

## 4. 质量复核

1. 首次进入照片复核应默认选择“发现问题（建议优先）”；验证“技术健康度低于 70”、
   “已有模型结果”和“全部已分析”等筛选，不要求逐张确认全部文件。
2. 点击“平均技术健康度”旁的问号，确认解释弹窗可关闭；照片复核卡片应始终显示“技术检测”，
   所有卡片都应显示等高的“技术检测”和“模型分析”摘要；无模型结果时明确显示状态，不能留下
   无含义的大块空白。进入详情后标题仍使用“技术检测 / 模型分析”，两者不能互相覆盖。
3. 点击缩略图查看照片详情、EXIF、问题证据和建议。
4. 修改一张测试照片的人工星级并刷新，确认星级持久化。

## 5. 首页、详情与统计

1. 核对首页不再显示强制工作流漏斗，并正确展示图库摘要、最近照片和真正存在的待处理异常。
   同时核对“继续上次工作”、最近相册和摄影摘要；这些入口只读取现有数据，不启动分析。
2. 在照片详情中使用左右方向键切换，确认不会跳出当前照片集合。
3. 核对 JPG+RAW 标识、快门/光圈/ISO/焦距及扩展 EXIF。
4. 核对亮度直方图明确标注基于 JPG，不把它理解为 RAW 动态范围。
5. 核对总分、曝光、清晰度、参数评分条与已有技术结果一致。
6. 从摄影统计点击相机或月份，确认进入的图库筛选正确。
7. 在详情页切换“精简 / 标准 / 完整”，确认高级拍摄信息和富士机内配方按层级显示，刷新后偏好仍保留。
8. 在质量分析页核对“详情数据”待补数量；补全任务只读照片，并支持暂停、继续和安全取消。
9. 在相似组内只排除一张照片，确认该组仍在“待选”；入选一张或全部排除后才离开待选列表。
10. 打开照片详情并滚动到最下方，确认底层图库不移动；切换窄窗口后确认整个详情仍可滚动。
11. 点击“沉浸查看”或按 `F`，验证左右切换、适应窗口、缩放、信息栏和 `Esc` 退出；浏览器全屏按钮应作为可选增强。
12. 点击关键拍摄参数后的问号，确认解释卡片说明当前概念、常见选项和品牌差异；点击外部、关闭按钮和按 `Esc` 均能关闭，`Esc` 不应同时关闭照片详情。
13. 进入组内对比，确认“下一组待选”位于标题区，“调整这一组”位于照片说明区；进入调整页面后不再显示“下一组待选”，取消调整应回到当前组普通对比页。
14. 进入连拍选片后可在“全部相似组 / 相册”之间切换；进入相册后确认默认“只看待选”，待选数、总数、分页和“下一组待选”都限制在该相册。
15. 新建包含至少两张照片的分组并保存，确认页面直接显示新生成的第一组；只有一张照片的分组应阻止保存并提示放入“移出分组”。再次进入该组应先显示照片，而不是调整界面。
16. 连续进行两次人工拆分，等待撤销提示消失后进入当前组的“调整这一组”，依次使用“撤销上一次调整”确认能逐步回退；“恢复自动识别”应一次移除整批人工拆分，且不修改照片文件。
17. 从调整分组页面切换到其他主功能，再次进入连拍选片，确认回到相册选择页，不保留原组或编辑状态。
18. 完成“更新相似分组”后进入质量分析，确认视觉预筛完成消息只在相似组选片页显示。
19. 图库中展开和收起筛选面板，验证生效条件标签可单独移除，“全部清除”会保留相册详情上下文。
20. 完成“更新相似分组”后停留在相似组选片页，确认完成结果可手动关闭，并会在约 8 秒后自动消失；失败结果不自动隐藏。
21. 进入摄影统计，确认头部显示拍摄天数、相册数、质量分析覆盖和平均技术健康度，不再重复显示相似选片进度；点击相机、镜头和月份仍可正确钻取。
22. 进入设备管理，在富士 X 卡口目录切换“全部 / 已拥有 / 未拥有”，将一款测试镜头标为已拥有后刷新页面确认保留，再改回未拥有。该操作只写当前工作目录的 `Equipment/inventory.json`。
23. 核对设备页顶部为机身、下方左侧为镜头且默认“已拥有”、右侧为附件；分别用测试内容新增并编辑一项机身、镜头和附件，刷新确认保留，再删除测试项目。官方镜头只切换拥有状态，不应从官方目录消失。
24. 编辑一个 EXIF 已识别设备，确认原始型号不可修改、显示名称和备注可修改，保存后历史拍摄量不变；隐藏后可在“已隐藏设备”恢复。尝试新增同型号机身或镜头时应提示已存在。
25. 关闭或等待已完成任务提示消失后刷新页面，确认同一条完成消息不会再次出现；失败消息仍应保留供排查。
26. 确认质量分析概览固定在页面顶部，下方横向切换“照片质量 / 模型建议 / 运行记录”；提示词版本和结构警告只在运行记录的高级诊断中出现，页面不再重复展示“最近完成”。
27. 在相似组选片中切换“待选 / 已完成 / 人工调整 / 全部”；拆分保存后应直接显示新组，返回列表后可在“人工调整”找到仍生效的修改。首页“待处理”应显示相似组待选数量。
28. 在折叠连拍的相册中点击“选择照片”，打开一张组卡后逐张勾选，确认“人工入选 / 技术推荐 / 全选 / 清空”只影响本次临时选择，最终导出数量与确认数量一致。
29. 在摄影统计切换“概览 / 拍摄参数 / 时间趋势”以及“数量 / 占比”，确认统计值一致且相机、镜头、题材仍可正确钻取。
30. 在应用设置中分别打开照片、工作、缓存和报告目录，确认只能打开当前实际配置目录；在后期输出分别生成“相似组人工保留 / 已有评级 / 指定相册 / 全部照片及状态”清单并核对数量。所有清单仍只写报告目录。
31. 分别进入照片图库、相似组选片和质量分析，确认都有横向“全部 / 相册”范围；点击同一相册进入详情后，在“照片 / 连拍选片 / 质量分析”之间切换，确认相册范围不丢失，返回相册时回到相册列表而不是临时调整状态。
32. 升级 schema 21 后打开一张测试照片，在“标签与流程”中多选题材和问题、选择一个工作状态并添加自定义地点；刷新后确认保留。切换工作状态应替换旧状态，不能同时保存两个；这些操作只写 SQLite，并同时作用于对应 JPG+RAW Capture。
33. 在图库筛选中分别选择题材、工作状态、人工问题和地点，确认可与相册、评级和质量条件组合；进入“选择照片”，选两张测试照片后使用“批量标记”，确认添加、移除和状态替换均只影响所选 Capture，刷新与筛选结果一致。
34. 升级 schema 22 后编辑一个隔离测试相册，在“本次拍摄使用的附件”勾选已拥有的脚架或滤镜并保存；刷新后应保持勾选，相册列表显示附件数，设备管理显示“用于 N 个相册”。取消勾选后两处统计应同步归零；全过程只写 SQLite，不修改照片或 EXIF。
35. 升级 schema 23 后分别打开普通照片和相似组选片详情：普通照片只显示星级，不显示保留/排除；相似组详情显示“保留此张/排除此张”，并明确只影响组内选优。工作状态目录不再提供“精选/待淘汰”，尝试自定义新增这两个旧状态应被拒绝。已有旧状态必须仍可显示、保留或移除，不能被升级自动改成选片结论。
36. 升级 schema 24 后，在连拍对比中将一张照片设为保留并勾选“表情差异”或“构图差异”；详情页和摄影统计应同步显示。点击统计理由或在图库筛选中选择该理由，应只显示对应人工保留照片。取消保留或改为排除后理由应清空。该操作只写 SQLite，不触发模型分析或修改照片。
37. 打开一个已有技术评分的相似组，确认默认按“推荐顺序”稳定排列并显示名次与相对理由；切到“拍摄顺序”后应按原序号排列。切换排序、刷新和重新进入都不得改变人工入选/排除，也不得启动新的质量或模型分析。
38. 在包含明显分差的隔离相似组中，确认显示“技术最佳 / 接近备选 / 候选 / 明显技术弱项”层级；弱项标签只能描述已有技术健康度，不能自动勾选排除。分差不足或未检测时不得武断标记为失败。
39. 在摄影统计概览核对“选片基准”：分母只能是至少有一张人工入选的相似组，Top‑1 表示人工入选包含技术最佳，Top‑2 表示人工入选落在推荐前两名。未处理组和仅全部排除的组不得降低命中率。
40. 打开一张已有 v4 模型结果的隔离照片，确认详情将“技术检测 / 模型分析 / 后期建议”分开；模型分析内继续区分“观察到什么 / 下次怎么拍”，画面问题带置信度和可修复程度，检测证据区分测量结果与规则推测。没有模型结果时只能显示技术检测证据，不得伪造模型分析；全过程不重跑模型、不写照片。
41. 在摄影统计概览核对“模型观察与后期建议”只按每张照片最近一次已完成结果汇总；点击一个常见模型观察后，图库应显示同名筛选标签并只返回包含该观察的照片。清除筛选后恢复全部照片，过程中不得启动模型任务。
42. 在质量分析同步已有题材结果，确认详情把分析题材标为只读来源，人工题材仍可独立增删；清除分析题材后人工/导入标签必须保留，再次同步应恢复相同结果。将最新模型结果标为“不准确”后，该结果的分析题材应退出统计和筛选。
43. 在摄影统计查看条件性关联，只应显示至少 3 张条件样本且至少出现 2 次的问题；界面必须说明相关性不代表因果。点击关联项后，图库应同时显示模型观察和关联条件，并只返回同时满足两者的照片。
44. 详情页参数化方案可从模型起点载入、归零、保存草稿、标记采用和暂不采用；保存后刷新仍保留，恢复旧版本会新增草稿而不覆盖历史。
45. 参数快速预览只改变缓存预览，正式照片、XMP 与 Lightroom 目录均无写入；界面明确说明不是 Lightroom 精确渲染。
46. 摄影统计“成长趋势”中的人工高星、技术低分、相似拍摄和选片保留率均显示分子/分母；点击月份只进入对应拍摄月。没有人工评级或明确取舍的月份必须显示空值，不能显示误导性的 0%，也不能自动宣称进步或退步。
47. 在设置页修改 Lightroom 目录与备份目录后，重启隔离服务核对只读预检；存在 `.lrcat.lock` 时只显示“目录使用中”，不得删除锁或打开目录数据库。准备清单应标出 RAW sidecar 候选、已有 XMP 和冲突复核数，`write_xmp` 与复制/移动执行字段仍全部为 0。
48. 在至少 3 张且已有指纹和技术健康度的隔离相似组中切换“技术推荐 / 兼顾差异 / 拍摄顺序”。技术最佳应保持首位；“差异候选”只能出现在技术合格且接近最佳的照片上，不得自动入选或排除，也不得把画面距离直接表述为已经识别出的动作或表情。
49. 打开隔离照片的参数化方案，展开“几何与细节调整”，分别预览降噪、居中裁剪和水平校正；旧 v1 历史应自动补零并可恢复为 v2 草稿。预览尺寸允许因裁剪变化，但缓存源文件、照片、XMP 和 Lightroom 必须保持不变。
50. 连续完成至少 3 个隔离相似组选片后进入成长趋势，核对选片会话数、平均活跃秒数和决策次数；未满 3 组时平均值必须为空。题材对照只显示至少 3 张样本并能钻取对应题材；修图反馈只汇总每张照片最新方案，不自动宣称采用建议后已经改善。
51. 将图库切到列表视图，核对照片、拍摄时间、相册/分组、大小和评价纵向对齐；每行只出现一次拍摄时间，小文件显示 MB/KB 而不是 `0.0 GB`，窄窗口不应把时间挤成无意义的两行。
52. 进入批量选择，分别验证“添加/移除标签”“归入相册”和“分享图长边”；归入操作只修改 SQLite 关联，分享包只写报告目录中的副本，按钮尺寸不应压过其他批量操作。
53. 打开“管理标签”，在隔离库新增、改名、停用和恢复自定义标签；正在使用的标签不允许删除，停用后照片已有标记不得丢失。内置标签只能停用/恢复，图库筛选只显示实际有照片的标签。
54. 在详情页核对拍摄参数翻译不再重复显示中英文或重复 AF-C；说明图标、分析可信度、备注保存、保留依据和后期建议保持紧凑，已有模型后期建议能从“完整详情与后期建议”进入。
55. 点击详情“打开原图”和“在资源管理器中显示”，以及相册列表“打开目录”，确认系统定位正确且照片内容、时间和大小均未改变；离线文件或没有来源目录的相册应显示错误而不是打开无关路径。
56. 设备管理为隔离测试设备配置 JPG/PNG/WebP 本地图片，确认刷新后显示；打开机身三点菜单时不应被下方镜头容器裁切，菜单和选中态不应变为黑底。删除图片路径后应恢复字母占位图。
57. 在图库列表、小图、中图和大图间切换，确认每种尺寸都能看到机身、镜头和 JPG+RAW 摘要；缺少 EXIF 时显示“器材信息未知”，不得凭空补值。
58. 展开图库筛选后进入“管理分类与状态”，确认它不是与“全部/相册”并列的内容范围；关闭管理弹窗后仍保留当前图库范围和筛选条件。
59. 在已有模型结果的详情中核对可信度备注占满可用宽度、保存按钮保持紧凑；参数化方案使用独立边框容器，展开标题不贴线，按住眼睛图标只临时显示原始缓存缩略图。
60. 相册列表中确认编辑、来源目录、确认和打开照片保持固定列；相册确认后确认按钮应消失，但打开照片不得移位。窄窗口允许操作换行，不应互相挤压。
61. 在相似组同一照片同时出现技术推荐、差异候选和组内保留时，标签应在右上角依次排列且文字清晰，不得与左上角名次重叠。
62. 进入设备管理的“已拥有”，确认 X-S20、XF23mmF1.4 R LM WR 和 XF70-300mmF4-5.6 R LM OIS WR 显示内置图片，并可分别打开作者来源和许可证；XC15-45mm 与 XF16-80mm 继续显示字母占位。为其中一项配置隔离本地图片后应覆盖内置图片，清空路径后恢复内置图片；不得新增拥有状态或联网热链图片。

## 6. 少量真实导入（需要时再做）

只在准备好后，将少量新照片手工复制到“待整理”，再选择或新建相册并运行“更新图库”。这一流程只增量索引并归入相册，不移动或改写新照片。全量质量分析和本地模型分析可继续延后。

## 7. 应用设置

1. 打开“应用设置”，核对配置照片目录与当前实际图库会分别显示。
2. 核对工作目录、缓存、ExifTool、RAW 扩展名及本地模型参数与 `config.toml` 一致。
3. 不必为了验收修改正式路径；如需验证保存，请使用隔离配置启动服务。
4. 保存后应提示重启生效并显示备份；不得移动照片、数据库或缓存。
5. 后台任务运行或暂停时，设置保存按钮应禁用，接口也应拒绝写入。
6. 使用隔离的全新工作目录启动空数据库，确认首页“开始设置”进入三步向导；照片、工作与缓存
   目录的“选择目录”应打开 Windows 原生选择器，取消选择不得改变输入值。
7. 向导中跳过 ExifTool 和本地模型仍可保存；确认页应明确只读、不移动删除、不写 XMP 且不
   自动运行模型。保存后只提示重启生效，不应立即扫描照片或移动旧工作数据。
8. 完成一次空目录扫描后重启，确认首页显示普通空图库说明，不再反复强制进入首次向导；完整
   设置页仍可修改全部目录和可选能力。
9. 运行自动测试确认 8 个品牌的合成元数据快照、无 EXIF JPEG 和损坏 JPEG 均通过；这些样例
   位于测试临时目录或 JSON 快照，不应出现在正式图库、相册或统计中。
10. profile 3 上线后，“详情数据”可能显示旧文件可补全数量；不点击补全时不得自动读取照片，
    点击后仍应支持暂停、继续和取消，且不得写入原片、XMP 或调用本地模型。
11. 在系统维护导出人工数据，解压/查看 JSON 确认不含绝对路径、GPS、照片、缩略图和模型结果
    正文。使用隔离数据库选择该文件，先核对匹配/缺失数量；未输入“恢复人工数据”时按钮不可用。
12. 在系统维护生成脱敏诊断包，确认数据库完整性显示正常；解压 ZIP 后应只有
    `diagnostics.json`，并确认其中没有照片、文件名/路径、GPS、设备序列号、人工备注/标签文字、
    模型提示词/响应/结果正文或原始错误消息。
13. 执行隔离恢复后核对评分、选片、备注、人工标签、当前分组、修图历史和设备配置；同时确认
    `Backups/AnalysisDatabase` 生成恢复前数据库备份且 integrity_check 为 ok。不得在正式数据库
    上为了验收覆盖数据；正式环境只需验证导出。
