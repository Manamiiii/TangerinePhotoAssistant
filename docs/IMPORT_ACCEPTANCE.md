# 自主导入验收

入口：侧栏、首页和照片图库的“导入新照片”。流程由本地系统实现，日常使用无需助手代操作。
开发验证使用自动清理的临时目录，不打开窗口、不操作鼠标，不操作正式照片或存储卡。

## 必要检查

1. 刷新已有页面，进入“导入新照片”。应看到四个步骤、来源选择和历史批次，主题、按钮与全局一致。
2. 选择一次实际准备导入的存储卡目录，或粘贴完整路径。无需手动创建待整理文件夹。
   点击“检查这批文件”，应显示文件/容量进度；检查完成前不复制文件、不创建相册。
3. 核对图片、RAW、视频、附属文件数量，以及完整重复组和不支持文件清单。
   如选择已经入库的旧存储卡批次，全量重复应提示跳过，不能以此测试新增复制。
4. 默认选择“新建相册”，输入符合既有习惯的“日期 · 主题”，选择类型，也可改为已有相册。
   未确认范围前不能复制。确认后点击“复制并导入”，观察复制校验、读取参数及入库进度。
5. 入库完成后应停留在本页，显示目标相册和归档入口。点击“查看相册照片”才进入相册。
   照片张数按 JPG/RAW 拍摄单元计算；视频和附属文件在独立清单，不冒充照片张数。
6. 点击“完成归档”，核对正式目录和全部文件后输入确认文字。归档完成后，本批状态应为已归档；
   照片、视频及附属文件的路径在正式相册目录下，本批已校验的待整理副本消失，存储卡原片仍在。
   若批次原来就在待整理中，跳过、不支持或无关文件会保留，不承诺整个待整理目录清空。

这里只需用下一批真正准备导入的照片做一次端到端验收，不必另建测试图库或重复导入旧照片。
不要为验收人为拔卡、损坏文件或中断服务；这些故障边界由临时目录自动回归覆盖。

## 可选检查

- 文件数超过 40 时，逐文件清单顶部和底部分页同步；批次超过 20 时历史批次分页正常。
- 在导入运行中切到其他页面再返回，或刷新页面，仍可查看本批进度；来源和相册名称草稿在同一浏览器会话内保留。
- 改用已有相册追加新批次，已归档的照片保持原路径，新增批次使用独立子目录。
- 使用日常窗口尺寸和 Windows 缩放核对长路径、步骤条、文件列表和深浅主题。

## 恢复与边界

- 导入/归档失败显示原因并保留来源和已复制资料。恢复原存储卡路径与存储条件后，在本页继续对应批次。
- 暂停导入仍占任务槽；不允许通过开始另一批、扫描或重启掩盖未完成任务。当前没有放弃已开始复制的批次并自动清理功能。
- 新导入单批最多 10,000 个支持文件；不支持文件单列，不自动复制或删除。
- 既有已入库照片的待整理批次应从相册归档；未分配的视频、附属文件可选择所在的独立待整理目录纳入相册。
- 视频本轮支持复制、校验、相册关联和归档清单；播放、剪辑及视频分析不在本轮范围。
- 正式目录使用 `类型/年份/相册名称/导入-批次编号/原相对路径`。未知拍摄年份归入“日期未知”。
- 不运行模型，不写 XMP，不操作 Lightroom，不清理存储卡，不改历史 `D:\Photo`。

## 自动化覆盖

临时文件回归覆盖整批导入/归档、来源字节保留、JPG/RAW/sidecar 成组去重、无关待整理文件不入库、
已扫描无归属视频纳入、同名批次追加、移动相册时附属文件归属、中断后重入、身份稳定、路径/链接拒绝、
来源变化和目标冲突、连接失败、任务恢复及写入互斥。前端 DOM 回归覆盖确认、新建相册、API 提交、
分页、草稿恢复、暂停恢复及后台忙碌保护；真实界面外观仍由上面的必要检查确认。
