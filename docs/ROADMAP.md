## 当前优先级

### P0：Windows 正式库收口

- 主备库版本/完整性、健康状态及正式只读查询基线已于 2026-08-31 核验，结果见
  `PERFORMANCE_BASELINE.md`；正常重启加载查询优化后补页面端到端延迟，不重复升级。
- 用正式数据回归 schema 27–32 的工作队列、完整性调查、任务异常、固定模型基准和相似组抽检。
- 不为验收启动全量质量或模型分析，不写照片、XMP 或 Lightroom。

### P1：降低工程复杂度

- 按 library、analysis、albums、system、exports 拆分 `webapp.py` 的 router、请求模型与任务编排。
- 将 `main.tsx` 剩余领域加载、分页和写操作迁入 feature controller/hook。
- 将 `styles.css` 按共享基础和 feature 拆分；先建立关键页面截图/响应式回归，避免视觉漂移。
- 将 schema 升级改为显式逐版本迁移；普通业务连接只配置连接策略。
- 从 FastAPI OpenAPI 生成 TypeScript API 类型，移除重复手写契约。

每批只移动一个边界，保持现有 API、数据语义和用户交互，并通过完整自动测试。

### P1：大图库与人工治理

  已实现先分页 ID 再计算展示字段；目前保留页码跳转，后续随数据增长复测。

## 需要单独授权的产品能力

以下能力不属于当前打磨和清理范围，必须先设计可恢复方案并由用户明确授权：

- 生成或写入 XMP、与实际 Lightroom Classic 版本做字段级合并。
- 自动应用修图、移动/重命名照片或操作 Lightroom 目录。
- 新的全量本地模型分析或长时间 GPU 任务。

## 暂缓能力

- 人脸身份聚类与人物命名。
- PSD、视频和复杂衍生文件的完整工作流。
- 自动删除、自动排除照片或基于模型结果的无人值守整理。

## 实施门禁

- 性能：先用 10k/50k/100k 脱敏数据和正式库只读基线证明问题，再优化。
- 模型：固定分层样本和高风险结果必须完成复核；结构错误超过 1%、人工不准确超过 10% 或出现
  越权建议时停止扩大批次。
- 相似组批量：仅处理预览通过的低风险组，最多 100 组，可整体撤销且稳定抽检；从不自动排除。
- 人工队列：默认只显示新发现、重新出现和已到期项，保存稳定指纹与首次/最近发现时间。
- 工程：每批通过 Python 测试、Ruff、前端测试、生产构建和对应隔离冒烟后才提交 `main`。
